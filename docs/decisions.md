- 2026-10-11 — The link check fetches only public hosts: it resolves every hop and skips loopback, private, link-local, shared, documentation, multicast and reserved addresses (a `node:net` BlockList), including IPv4 addresses carried in IPv6 — mapped `::ffff:0:0/96` and compatible `::/96` in dotted or hex form, NAT64 `64:ff9b::/96` and `64:ff9b:1::/48`, 6to4 `2002::/16` — follows at most 5 redirects by hand, and reads no body. `fetch` resolves the name again, so a DNS-rebinding host could still answer the request from a private address in that window; accepted because the check runs on a GitHub-hosted runner and reports only a status code and final host. So the registry has to be at the repo root, while sources can stay with the Next.js app. A local install of the generated item JSON into a fresh Next.js 16.4 + shadcn app built successfully; `shadcn registry validate` and `shadcn build` accept the generated registry offline.
