# Decisions

One dated line per non-obvious decision, newest at the bottom. Format: `- YYYY-MM-DD — <choice>. <why>.` The PR that made the change holds the detail.

- 2026-10-11 — Adopted the v1.2 plan ([`v1.2/plan.md`](v1.2/plan.md)) and its cleanup plan ([`v1.2/repo-cleanup.md`](v1.2/repo-cleanup.md)): library first, Sources second, GitHub issues and PRs as the backend, no accounts or database. A directory of links alone can't answer whether Tessli improves AI-built UI; explained, installable items and a measured bench can.
- 2026-10-11 — Code and taste notes are MIT-licensed; the Tessli name, wordmark and hero artwork are excluded and covered by `TRADEMARKS.md`, with Online Scope as rights holder. The hero artwork's origin is not recorded, so it is excluded from the licence regardless of how that is later resolved.
- 2026-10-11 — Saved and Boards are removed from v1.2. They need accounts or sync to be useful beyond one browser, and v1.2 builds no accounts.
- 2026-10-11 — The "keep all 295 rows" rule is replaced by "never drop a source row silently; archive it with a reason". Pruning to a defended list needs removals, but IDs, history and old links must survive.
- 2026-10-11 — The source list follows [`v1.2/catalogue-triage-final.csv`](v1.2/catalogue-triage-final.csv). It is the owner-approved triage of the audit.
- 2026-10-11 — The registry location is settled by the stage-B spike, preferring `web/registry/`. It is the simplest fit with the Next.js app; CODEOWNERS already lists it.
- 2026-10-11 — Code of Conduct reports go privately to the maintainers via the contact on their GitHub profiles (@itsdeepaks, @deepak-onlinescope); a dedicated contact address is an owner follow-up. No address is published until one exists.
- 2026-10-11 — CODEOWNERS defaults to `@itsdeepaks @deepak-onlinescope`. Both are the owner's accounts with write access.
- 2026-10-11 — Stale draft PR #99 is closed as superseded by v1.2. Its work predates the new direction.
- 2026-10-11 — Merged branches are listed for a human to delete rather than deleted by automation. The automation environment's proxy rejects remote ref deletion.
- 2026-10-11 — Process docs (PRD, build slices, slice evidence, contracts, handoffs, research, archive) are removed from the tree. The PR and diff are now the record; everything removed is recoverable from the `v1.1-archive` tag and the `archive/v1.1` branch.
- 2026-10-11 — The issue forms apply the labels `source:suggestion`, `source:problem`, `design:needs-implementation` and `bug`; a human must create any that are missing in the repository settings. GitHub does not create labels from issue forms, so until then issues arrive unlabelled and the triage in `CONTRIBUTING.md` will not work.
- 2026-10-11 — C6 port candidates from brand-preview (removed in C2; read it with `git show v1.1-archive:brand-preview/styles-components.css`). Worth carrying into the C6 primitives:
  - Shared-border grids: the container draws the top and left border, each cell the right and bottom, so swatch, type and card grids never double their borders.
  - One uppercase micro-label style (about 0.72rem, weight 700, 0.06–0.11em tracking, muted or accent text) shared by section kickers, fieldset legends and field labels.
  - Tabs marked by a 2px accent underline on `[aria-selected="true"]::after`, and a segmented control whose `[aria-pressed="true"]` option inverts to strong text on surface.
  - Selected tags tinted with `color-mix()` of the accent into the line colour and `--accent-soft`; success notices tinted the same way from `--success`.
  - A `kbd` style with a heavier bottom border, and primary/secondary/quiet button variants (raise the specimen's 42px height to the 44px touch target).
- 2026-10-11 — `resource-card-browser` now checks hover lift, border trace, selectable text and overflow on `/resources` cards instead of the removed `/lab/resource-cards` fixtures; the fixture-only checks (fixture count, Save click announcements) went with the fixtures. The media fallback chain is checked at runtime by forcing image errors on one Browse card and asserting `data-media-state` moves preview → favicon → generated mark. The override variable is now `TESSLI_BROWSE_URL`. The card behaviour is kept, so its browser coverage is kept on the real Browse surface.
- 2026-10-11 — C3 leaves two kinds of `supabase` text in the tree: the preview-pilot reports in `docs/reports/` (removed with the media pipeline in C5) and three third-party preview-image URLs in `lib_data/resource-media.json` and `web/data/catalogue.json` that providers host on `supabase.co`. The reports belong to C5's scope, and the image URLs are facts about other sites, not Tessli's use of Supabase. The hosted Supabase project (user schema, preview bucket) still exists outside the repository; decommissioning it is an owner follow-up.
- 2026-10-11 — C3 keeps `NEXT_PUBLIC_SITE_URL` in `web/.env.example` (it sets the robots and sitemap origin) and replaces the `supabase` term in three negative test guards with a generic SDK-client check (`create(Browser|Server)?Client(`). The guards still block client SDKs and network calls in those components; the package itself is gone, so any import of it now fails typecheck and build.
- 2026-10-11 — C4 removes `components/toast-notification` rather than keeping it as an unused primitive. Saved was its only user; an unused component is dead weight, and it is recoverable from the `v1.1-archive` tag if C6 needs one.
- 2026-10-11 — C4 replaces the removed Boards calls to action with in-page links instead of leaving empty action rows: the `/for-ai` hero's second action is now "Set up local MCP" (`#local-mcp`), and the collection-detail hero action is now "Start with stage 1" (`#research-sequence`). Copy that told people to save sources or keep decisions in a Board now says to keep decisions in their own project notes. Both pages keep their layout, and no new feature is implied.
- 2026-10-11 — The homepage hero fact "Private — Browser-local saves" becomes "No account — Needed to browse". Saves no longer exist, the four-fact row keeps its grid, and the new fact is true (v1.2 has no accounts).
- 2026-10-11 — `llms.txt` replaces "No Board or Saved data is public" with "No accounts: Tessli has no sign-in and keeps no user workspace"; the MCP and public-representation boundary text says "browser data" instead of naming Boards or Saved. The boundaries still hold; they no longer name removed features.
- 2026-10-11 — `docs/ref-img/saved-desktop.webp` is removed with the Saved page it described, along with its `design.md` and `asset-manifest.md` entries. It is recoverable from the `v1.1-archive` tag.
- 2026-10-11 — C5 removes the Coverage row, the coverage note and the "Recorded references" evidence list from the Source Guide's "Source details" panel, and nothing else on that page. The plan drops the Verified and evidence machinery from the public UI, and the verification library had no UI importer to take it with it; the governance list, the honest Listed fallbacks and the "does not imply live provider verification" note stay. The source-profile contract, the profile JSON (evidence included) and the MCP and representation fields are unchanged until the B1 data-model change.
- 2026-10-11 — C5 deletes `generate-intelligence-profiles.mjs` without a replacement: the committed JSON under `web/data/intelligence-profiles/` and `intelligence-profile-batches/` is now edited directly and validated by `npm run profiles:check`. The generator held the same data a second time as hard-coded values.
- 2026-10-11 — C6 renames the body font-size token from `--text-body` to `--text-body-md`. Both the colour and the size were declared as `--text-body`, so the size won and every `color: var(--text-body)` fell back to `--text-strong`; body copy (hero lede included, without touching the hero files) now renders in the designed `#4f4a44`.
- 2026-10-11 — C6 replaces the undefined `--space-7` and `--space-9` with `--space-6` and `--space-8` rather than adding steps to the scale. They computed to 0 before; rounding down keeps the documented 4px scale and the smallest visible change.
- 2026-10-11 — C6 keeps `--accent` as Tessli's orange signal and adds only `--accent-foreground` (charcoal) for the shadcn alias set. Renaming the orange would touch 63 references and the frozen hero; stage-B preview themes can rescope `--accent` inside the preview.
- 2026-10-11 — C6 makes the shared primary `Button` orange with charcoal text (design.md §6), with the `--radius-control-md` control radius. The collection-detail, error and placeholder primaries were charcoal and the For AI actions were square; one primary style replaces the drift.
- 2026-10-11 — C6 removes eyebrows everywhere except the home hero. Where the label carried information it stays as plain text: the public pages keep their page name as a sentence-case `label`, and the source page shows its category as a `Tag`. Numbered markers stay on the For AI workflow, the home research loop and Collection stages (real sequences); the For AI "01/02" access cards lose theirs. Internal `→` arrows (text and card icons) are removed; `↗` stays on external links.
- 2026-10-11 — C6 moves the `next/font` variables from `<body>` to `<html>` so `:root` tokens (`--font-display`, `--font-ui`) can resolve them.
- 2026-10-11 — C6 leaves the `1100px` Browse/Collection grid breakpoint and the hero's `720px`, `389px` and `1120px` (facts) breakpoints in place. Moving `1100px` would change real laptop layouts between 1025 and 1279px, and the hero is frozen in this step; every other one-off breakpoint now uses 480, 767 or 1023px.
- 2026-10-11 — C7 stops tracking `web/next-env.d.ts` and lists it in `.gitignore`, as current Next.js guidance does. `next build` rewrites it (adding a `.next/types/routes.d.ts` import), which dirtied the tree on every build; `npm run typecheck` passes on a clean checkout without it because the app's own `next` imports bring in Next's global types.
- 2026-10-11 — C7 folds every runtime assertion of the deleted `release-gate-browser.mjs` that still covers kept behaviour into `smoke-browser.mjs`: page statuses and server-rendered text, removed routes (`/auth`, `/saved`, `/boards`) staying 404, `robots.txt` and `llms.txt` contracts, and the source and collection `profile`/`collection` JSON and Markdown routes (headers, HEAD, OPTIONS). The Browse card checks were already in `browse-pages-browser.mjs`. Full-page screenshots are taken at 1440 and 390 as C7 specifies; every smoke page still gets the landmark, single-`<h1>`, header/footer, console-error and no-horizontal-overflow audit at the old release gate's other widths (1280, 1024, 768, 430 and 360) without screenshots, so no overflow coverage is lost. The old CI step's curl-and-grep checks on `/resources` and `/for-ai` moved into the smoke test too, so the local browser gates run them.
- 2026-10-11 — The smoke test also renders `/submit` and the 404 page, which the old release gate screenshotted, and fails on any console error, uncaught exception or same-origin network error. It ignores network errors for third-party source media (previews and favicons hosted by the sources): the media fallback chain covers them and CI cannot keep other sites reachable.
- 2026-10-11 — `ci.yml` lists each browser test by name and fails if a `web/tests/*-browser.mjs` file is not listed, so a new browser test cannot be skipped silently. The weekly `links.yml` caches lychee results for 3 days (so scheduled runs always recheck every URL; the cache only speeds up a manual rerun), accepts 2xx, 403 and 429 (sites that block bots or rate-limit are not reported as broken), and only opens or updates one "Broken source links" issue when lychee exits 2 (broken links); any other lychee error fails the run instead of posting an issue. It never edits or archives a source.
- 2026-10-11 — Source IDs are frozen: every row now stores its ID explicitly (copied from the current catalogue, identical to `v1.2/catalogue-triage-final.csv` for all 295 rows), and the generator reads it instead of hashing the URL. Fixing a URL (Origin UI → coss, React Aria, v0) must not change an ID, or collections, profiles and old links break.
- 2026-10-11 — Sources live as one file each, `sources/<slug>.yml` (295 files), validated by `schemas/source.schema.json` with ajv; `lib_data/design-resource-library-295.csv` and its `.md` twin are removed (recoverable from `v1.1-archive`). The generator still writes `web/data/catalogue.json` deterministically and offline. One file per source means a community PR touches one small file and PRs don't conflict.
- 2026-10-11 — `yaml` 2.9.1 (eemeli/yaml) is added as an exact-pinned devDependency to parse `sources/*.yml`: zero-dependency, maintained, YAML 1.2 (so `2026-07-22` stays a string and `no` stays a string). Node has no built-in YAML parser and a hand-written one would be riskier than the dependency.
- 2026-10-11 — `kind` is a provisional category-level default, not a per-source judgement: website-inspiration, product-ui-ux and landing-marketing → `gallery`; ui-libraries and motion-3d → `library`; design-systems → `design-system`; typography, icons and visual-assets → `asset`; color-accessibility and design-tools-ai → `tool` (`reference` is unused so far). No existing field records what each source is, so a finer `kind` needs a curator per source (B1b).
- 2026-10-11 — The 11 current category ids stay. The revised 13-category taxonomy in plan §7.3 needs a curator to place each source, so it is deferred to the triage step rather than guessed by mapping.
- 2026-10-11 — Each `summary` is the existing description verbatim, even where it is shorter than 40 characters. The 40–200 character guideline applies to new submissions; rewriting 295 descriptions is curation, not migration.
- 2026-10-11 — `added_at` is 2026-07-22 for all 295 sources: commit `c759547` created the CSV with every row, and the CSV was unchanged until this migration, so that is each row's real first appearance in git history. `last_checked` is `null` everywhere: no recorded human check exists, and the August media fetches checked previews, not the sources.
- 2026-10-11 — `best_for` and `limitations` are copied verbatim from the 40 intelligence profiles only where the profile's list fits the plan's caps (best-for at most 3: 36 sources; limitations at most 2: 18 sources). Trimming a longer list is a curator choice, so those sources omit the field and the site keeps reading the full list from the profile JSON, which stays on disk; a test checks the YAML copies never drift from their profile.
- 2026-10-11 — The curated Browse order is kept in `lib_data/source-order.json` (an ID list). Sorting the files by name would have reshuffled "Curated order" on `/resources`; a new source that is not listed simply follows the listed ones, by category and then name, so contributors never need to edit the list.
- 2026-10-11 — `web/data/catalogue.json` moves to version 2: it drops `subscriptionRequired` (it copied `access`), `usefulFor` and `tags` (empty everywhere) and `previewSource` (no consumer; the provenance stays in `lib_data/resource-media.json`), keeps `domain` derived from `url` at build time, and adds `kind`, `addedAt`, `addedVia`, `lastChecked` and the optional plan fields. The generator and catalogue schema no longer expect 295 rows, fixed per-category or per-access counts, or exactly 11 categories; they check structure, uniqueness and references instead.
- 2026-10-11 — New source IDs are `resource-` plus the slug (the 295 migrated IDs keep their old URL-hash form). An ID only has to be unique and frozen; a readable one is easier to review in a PR.
- 2026-10-11 — Public counts (home facts, About, 404, the lab specimen) are derived from the catalogue and count non-archived sources, so they always equal what Browse lists; `needs-review` sources are still listed and counted until a curator archives them. The category count is the number of categories that hold at least one listed source.
- 2026-10-11 — Archived sources stay in `catalogue.json` and keep their page and `profile.json`/`profile.md` (all marked `noindex`), resolvable by exact ID or slug in the MCP `get_source` tool with their reason and replacement. Browse, home search, collection pages and their JSON/Markdown, the sitemap, the MCP search, alternative, collection and brief output, and every count use only non-archived sources. A collection stage left with no listed source is hidden; collection membership itself is fixed in the PR that archives the member (B1b).
- 2026-10-11 — The Listed/Profiled/Verified coverage levels, verification dates, evidence counts, coverage notes and governance lists are removed from the source page, `profile.json`/`profile.md` (contract `tessli.public-source.v3`, which adds `status`) and the MCP tools, as plan §7.3 drops that machinery from public surfaces. The source page's "Recorded governance" list goes with it (C5 kept it until this data-model change), its "Availability" row becomes "Status", and "this Listed source" fallbacks now say "this source". The unregistered `getNativeResourceProfile` adapter, whose only job was exposing the raw profile for the removed parity checks, is removed.
- 2026-10-11 — The 40 intelligence profiles stay on disk unchanged, evidence and governance included. Their schema and `profiles:check` require those fields, and trimming them changes no page; they are simply no longer read by any public surface.
- 2026-10-11 — `check-source-profile-contract` keeps running (contract v2): it still checks identity, access, status, archive fields, access routes, intelligence normalization and ID/slug lookups, and now also that browsable sources are exactly the non-archived ones and that every intelligence profile links to one source. The fixed 255 Listed / 40 Profiled / 0 Verified composition and the exact-40-profiles count are dropped with the coverage levels.
- 2026-10-11 — `web/data/catalogue.json` and `catalogue-validation.json` are listed in `web/.prettierignore`. They are generated, `catalogue:check` enforces their exact bytes, and Prettier would otherwise collapse the new short arrays the generator writes expanded.
